# Terraform for AI Infrastructure: a local measurement lab

**Question.** Can one HCL codebase rebuild a local AI platform stack the
same way every time under both OpenTofu and Terraform, and can a refresh
plan and Rego policies catch injected drift and insecure settings, at
zero spend?

**Headline.** OpenTofu v1.13.9 and Terraform v1.17.1 planned the
13-resource stack identically (13 of 13 addresses) and rebuilt it
identically in 20 of 20 runs each; a refresh plan caught 38 of 54
seeded drift changes (recall 0.70, Wilson 95% interval 0.57 to 0.81,
one detection above the locked 0.70 cut) and missed every permission
change and unmanaged file; the Rego policies reached precision 1.00
(95% interval 0.88 to 1.00) and recall 0.93 (28 of 30, 95% interval
0.79 to 0.98) on a 60-file corpus built from the same fields they check.

**Field.** Systems and infrastructure, reliability. **Job family.**
Infrastructure and platform engineering.

**Verdict.** Functional. Tests pass in CI on Python 3.11 and 3.12, the
studies ran end to end with real engines and their per-run and
per-trial records are in results/, and RESULTS.md regenerates unchanged
from them in CI. SPEC.md and HYPOTHESES.md were committed in fee401d
before any code or result (tag proposal-v1), so the lab is
pre-registered. Not Evaluated: the reliability profile's stated
recovery targets, timed restore drills, alerting and runbook are not
part of this study, and the raw RQ1 plan and state JSON are not
committed, so a reviewer cannot re-derive 13 of 13 without re-running
both engines (REPORT.md, "Field profile").

Live dashboard: https://jesunahmadushno.github.io/terraform-for-ai-infrastructure/
(built from results/, corpus/ and policy/; its policy playground runs a
JS port of policy/policy.rego, checked file by file against
results/rq3_policy.json at build time).

## Reproduce

Checks, anywhere (no engines needed):

```text
python -m pip install pytest
python -m pytest -q
python -m harness.generate_results_md && git diff --exit-code RESULTS.md results/summary.json
```

Full studies (OpenTofu, Terraform and conftest on PATH; versions and
download hashes in AUDIT.md; no cloud account, credential or spend):

```text
python -m harness.rq1_plan_equivalence
python -m harness.rq1_reproducibility
python -m harness.rq2_drift
python -m harness.generate_corpus
python -m harness.rq3_policy
python -m harness.generate_results_md
```

## Hypotheses

Pass lines are locked in HYPOTHESES.md; verdicts are computed by
harness/generate_results_md.py.

| Hypothesis | Verdict | Measured result |
| --- | --- | --- |
| H1 plan equivalence | Supported | 13 of 13 addresses match, same type and actions, match rate 1.0000 |
| H2 rebuild reproducibility | Supported | 20 of 20 runs match run 1 for each engine; plan and state hashes identical across engines in the recorded run |
| H3 drift detection recall | Partially supported | Recall 0.7037, 38 of 54; managed only recall 0.8261; misses are only permission changes and unmanaged additions |
| H4 policy precision and recall | Supported | Precision 1.0000, recall 0.9333; TP 28, FP 0, TN 30, FN 2 |

## Layout

Files named in the locked SPEC.md and HYPOTHESES.md keep their names;
the second column gives the role each plays in the portfolio standard.

| Path | Role | What it holds |
| --- | --- | --- |
| SPEC.md, HYPOTHESES.md | proposal | The locked plan and pass lines (fee401d, tag proposal-v1); a test fails if one byte changes |
| REPORT.md | report | Background, method summary, results against the pass lines, misses, threats, review, future work |
| METHODS.md | report (method) | Full method, written after the lock and before results were interpreted |
| RESULTS.md | results | Verdicts and counts, generated by harness/generate_results_md.py |
| results/ | evidence and results | Per-run, per-trial and per-record study output; summary.json; the claim-check record |
| AUDIT.md | evidence | Tool versions and download hashes, licence, cost, security and claim audit |
| DECISIONS.md | decisions | Hard-to-reverse choices D1 to D12 (stands in for docs/decisions/) |
| lab/stack/ | code | The test object: 13 local_file resources, hashicorp/local 2.5.2 |
| policy/ | code | Five Rego deny rules |
| corpus/ | evidence | 60 labelled plan JSON files and labels.json, generated |
| harness/ | code | Study scripts, corpus generator, results generator (stands in for src/) |
| tests/ | tests | Harness unit tests, results consistency, layout and lock checks |
| site/ | dashboard | Live dashboard, built from results/, corpus/ and policy/ |

There is no experiments/ folder: the raw study output lives in results/
next to the generated summary, because the locked SPEC.md names
results/ for it.
