# METHODS

## Design

One fixed local stack, defined in lab/stack/main.tf, is the single test object for RQ1 and RQ2. It holds 13 local_file resources: 10 service definitions built from a map, a platform manifest, a policy manifest and a stack readme. File contents are deterministic JSON built with jsonencode from fixed variable defaults. No random resource is used, because a random value would change the state hash by design and would measure the random generator, not the engine.

The policy study, RQ3, does not apply anything. Its test object is a corpus of plan JSON files under corpus/, generated by harness/generate_corpus.py with labels set by construction.

## Engines and tools

- OpenTofu, primary. Version and download hash are in AUDIT.md.
- Terraform, comparator. Terraform is source available under BSL 1.1, not OSI open source. Version and download hash are in AUDIT.md.
- conftest with OPA, for RQ3. Version and download hash are in AUDIT.md.
- Provider: hashicorp/local, version 2.5.2, pinned in the configuration. The lock file is kept between runs of a study because it pins provider selections. It is not committed per engine, because the two engines record different registry hosts in their lock files. That difference is itself noted in the limitations in REPORT.md.

## RQ1 plan equivalence

Steps, in harness/rq1_plan_equivalence.py:

1. Clean the stack directory: state, build output, plan file and provider directory are removed.
2. Init with one engine, with up to 3 attempts. Init is not a measured step. Registry access on the build VM showed transient timeout spikes, so a retry is used and is recorded here. No measured value depends on init.
3. Run plan, save the plan, export plan JSON with show -json.
4. Normalise: keep resource address, resource type and planned actions, sort by address.
5. Repeat for the second engine on the identical directory and configuration.
6. Compare address by address. A match needs the same type and the same actions.

Metric: matches divided by addresses compared. Thresholds are in HYPOTHESES.md, H1.

## RQ1 rebuild reproducibility

Steps, in harness/rq1_reproducibility.py, per engine:

1. Clean and init once.
2. For run 1 to 20: plan from the current empty state and hash the normalised plan, apply, read state JSON with show -json and hash the normalised state, destroy, record wall time.
3. Normalised state: from values.root_module.resources, keep address and the values for filename, content, file_permission and id, sorted by address, hashed with SHA256 over a compact JSON encoding. Lineage, serial and timestamps are excluded because only resource values are read.
4. A run matches if its plan hash and state hash both equal the run 1 hashes for that engine.

Metric: runs matching run 1, out of 20, per engine, with median wall time. Thresholds are in HYPOTHESES.md, H2.

Threat: the plan hash is taken from an empty state each run, so it tests plan determinism and apply determinism together. A separate empty plan after apply would always be empty by construction and adds no information, so it is not used.

## RQ2 drift detection

Steps, in harness/rq2_drift.py, with OpenTofu as the engine:

1. Build the mutation list in code: every managed file crossed with every mutation type gives 78 combinations. A seeded shuffle with seed 42 selects 54, with a coverage repair step so every type appears. The full trial list with outcomes is in results/rq2_drift.json.
2. Per trial: destroy, apply fresh, make one out-of-band change outside the engine, run plan with refresh and detailed exit code, export plan JSON.
3. Detected: the plan exit code is 2 and the mutated address appears in resource_changes with an action other than no-op.
4. Naive baseline: a file exists check on the mutated file. It detects a delete only, by construction.
5. Misses are grouped by mutation type in the result file.

Mutation types: content edit, content append, file delete, file truncate, permission change, unmanaged addition. The unmanaged addition trial adds a new file that no resource owns. Its address field names the file that shares the trial slot, and detection for it means the plan reports that address, which by construction it cannot. It is counted in headline recall and excluded from the managed only recall, exactly as pre-registered.

Metric: recall is detected divided by trials. Thresholds are in HYPOTHESES.md, H3.

## RQ3 policy precision and recall

Steps, in harness/generate_corpus.py and harness/rq3_policy.py:

1. Generate 60 plan JSON files: 30 compliant, 30 violating. Violating types: public exposure 7, hard coded secret 7, encryption disabled 6, world writable permission 5, bind to all interfaces 3, secret in plain text content 1, secret under an alternate key name 1. Secret values are fixture markers with the prefix TEST-SECRET. They are not real credentials.
2. Labels are written to corpus/labels.json by the generator, before conftest runs.
3. Policies in policy/policy.rego deny: public exposure, bind to 0.0.0.0, a non empty api_key field, encryption_enabled equal to false, and file_permission 0777. Content is parsed with json.unmarshal. Content that is not JSON, and a secret under a different key name, cannot match these rules. Those two cases were pre-registered as expected false negatives.
4. Run conftest test once per file. A non zero exit code is a predicted violation.
5. Count true positives, false positives, true negatives and false negatives. Precision and recall are computed in harness/common.py, in code, not by hand.

Metric: precision and recall. Thresholds are in HYPOTHESES.md, H4. The baseline, syntax validation alone, detects none of the violations by design because every corpus file is valid JSON.

## Statistics

Counts are exact over the full run set. No sampling is used inside a study, so no interval is reported for the headline counts. Wall times are reported as median, minimum and maximum over the 20 runs. No multiple comparison correction applies, because each hypothesis has one pre-registered primary metric.

## Reproduction

- Tests: python -m pytest, with Python 3.11 or 3.12.
- RQ1 plan: python -m harness.rq1_plan_equivalence
- RQ1 rebuild: python -m harness.rq1_reproducibility
- RQ2: python -m harness.rq2_drift
- RQ3: python -m harness.generate_corpus, then python -m harness.rq3_policy
- Results page: python -m harness.generate_results_md

Engines must be on PATH or in the workspace tools bin, which harness/common.py checks as a fallback.

## Environment note: provider mirror for OpenTofu on the build VM

OpenTofu registry discovery timed out repeatedly from the build VM during this build, including three failed init attempts in one reproducibility start. The harness init retry in common.py was not enough for that spike pattern. The fix used for the recorded runs: a filesystem mirror holding the official terraform-provider-local 2.5.2 zip, with its SHA256 verified against the official SHA256SUMS file, and a CLI config file that points only the OpenTofu registry host at the mirror. Terraform runs used the direct registry. Same provider version and same provider binary in both paths, so plan, state and drift values are unaffected. See DECISIONS.md D11 and AUDIT.md.
