## Cost audit

Total spend: zero. No cloud account was opened, no AWS resource was created, no paid tier was used, and no new credential was created. Tool downloads and provider downloads are free release files. The Jev claim check used the existing programme gate credit, as with other tracks.

## Security audit

- No real secret exists in this repo. Corpus secret values are fixture markers with the prefix TEST-SECRET, asserted by a test in tests/test_harness.py, which also asserts that no live key prefix appears in the corpus.
- State files, plan binaries and build output are git ignored and were removed from the working tree before commits.
- The stack writes only inside lab/stack/build during runs.
- Policies deny world writable permission and hard coded secrets, and the stack itself uses permission 0644 and an empty api_key field.

## Claim audit

- Every measured number in README.md and RESULTS.md comes from a file in results/, generated by the harness. RESULTS.md is generated by script and is marked as such.
- Arithmetic was pre-computed in code: precision and recall in harness/common.py, recall fractions in the study scripts, and verdicts from thresholds in harness/generate_results_md.py.
- Jev claim check on the headline claim: gate claim_check, model jev-1.13.0, question supported, noul 0.52, route REVIEW under the standing claim_check bands (clear at 0.85 or above, block at 0.10 or below, review between). Input tokens 1046, output tokens 20. Record: results/jev-claim-check.json. On the REVIEW route the claim was verified by hand: RQ2 counts were recounted from the trial records and matched, and the cross engine plan and state hashes were reproduced in a direct spot rerun (plan hash prefix 08fac9cd, state hash prefix 4591811d, both engines).
- Run history honesty: the first reproducibility batch produced per engine plan hashes that differed across engines for an unisolated leftover state reason, while each engine still matched itself 20 of 20. That batch was discarded as the record and the study was rerun clean. The recorded file is the clean rerun, in which plan and state hashes are identical across engines. The discarded batch is named here so the record does not hide it.
- No novelty claim is made. Verdict Pack 02 records that a full differential testing literature search was not run.
- No production, cloud scale or serving claim is made.

## Grade

Self grade on the house 10,000 scale, floored, with itemized deductions. Grade: 7,350 of 10,000.

Deductions:
- Minus 600: one provider only. Equivalence, reproducibility and drift evidence is bounded to hashicorp/local.
- Minus 400: drift measured on one engine only. The cross engine drift comparison is deferred to ROADMAP.md.
- Minus 400: policy corpus is 60 files with one policy tool. No second tool comparator.
- Minus 300: CI runs the Python tests only. Engine runs are not in CI.
- Minus 250: no native engine test files in this pass.
- Minus 250: literature base is the verdict pack. No fresh full literature search was run for this build.
- Minus 200: lock file not committed per engine, a documented limitation in DECISIONS.md D5.
- Minus 150: wall time medians were measured on a shared VM under load, so timing is environment bound.
- Minus 100: one discarded reproducibility batch and one discarded plan equivalence attempt from registry timeouts, both recorded, cost process quality.

Total deductions: 2,650. 10,000 minus 2,650 is 7,350.

## Maintenance audit

- Rerun cost is low: the full set of studies took minutes on the build VM, dominated by apply and destroy cycles under shared load.
- The corpus generator and the mutation list are deterministic, with a fixed seed, so reruns are comparable.
- Tool upgrades must update this file with the new version and download hash before any new number is published.
